# VisionForge 与 DSH 集成

用户问"怎么装进 DSH、设置卡片在哪、图片怎么预览/下载、怎么卸载"时读这份文档。

## 安装到 DSH

| 场景 | 做法 |
| :-- | :-- |
| 推荐 | DSH 应用内 **插件市场 → 搜索 VisionForge → 安装**（desktop 版由 Electron 应用独占管理，装/卸、启用/禁用都走应用内；CLI 的 add/remove 对 desktop profile 会报"由应用独占管理"） |
| 命令行（非 desktop） | `npx dsh plugin add @lr611/visionforge` |
| 安装后 | 重启 DSH 会话（或新开会话），让客户端脚本（client.js）注册生效 |

卸载：DSH 应用内移除即可。插件只写自己的配置（`~/.modlens/`）和缓存（Windows 默认 `D:\VisionForge\out`），**不改写 DSH 官方文件、不影响原生功能**；移除后残留缓存可手动删除。

## 设置卡片

DSH **设置 → 插件/配置 → VisionForge 配置**（名称可能为"VisionForge 配置"）。卡片内：

- **引擎**：下拉选择 qwen / glm / openai / anthropic / gemini-api 等；选中后下方字段随引擎变化
- **密钥**：填写后以 `••••` 掩码保存；卡片永不把密钥回显给页面
- **接口地址 / 模型**：引导用户填写；留空用引擎默认
- **读图优先级**：official（先官方模型）或 plugin（先本插件引擎）
- **粘贴转路径**：开关
- **输出目录**：默认 `D:\VisionForge\out`

卡片提交的值写入 `~/.modlens/config.json`（与 CLI 同一个文件）。**AI 在引导时不要替用户填写密钥或具体地址，也不要复述它们**——卡片就是让用户自己填的。

## 图片预览 / 放大 / 下载行为

生成或编辑完成后，对话里输出的是紧凑缩略图 + 操作按钮：

- **缩略图**：默认 90px 级小图；插件客户端会尝试用 canvas 本地兜底渲染（即使宿主拦截 loopback http 图片也能显示）
- **点击缩略图**：在电脑系统图片查看器中打开原图（走本地服务 `/modlens/open`），可缩放查看
- **下载**：点击下载 = 把缓存图**复制为永久副本**到用户选择/默认位置（Windows 默认 D 盘根目录），并自动打开资源管理器定位到该文件；**不是自动保存**，用户点了才落盘
- 缓存图在 `outputDir` 下保留 3 天（插件启动时清扫过期文件），会话内历史图片在缓存仍存在时都可继续放大/下载

**调试线索**（AI 排查时）：预览/下载链路依赖本地 loopback 服务（端口 45999/46999/47999/48999 候选）。若图片完全不显示：`npx @lr611/visionforge doctor` 看服务端口是否存活；若放大/下载按钮无反应，多半是客户端脚本未生效（DSH 未重启）或缓存文件已被清理。

## 与官方模型的分工（读图优先级）

- 官方模型能原生看图（如 DeepSeek-V4-Pro (modlens vision)）：粘贴图片在输入框直接预览，读图走官方，无需插件介入
- 官方模型是纯文本：`visionPriority=plugin` 时粘贴图片由插件接管为路径文本，走用户配置的引擎读图；`official` 时先官方后插件
- **生图/编辑永远走插件**（官方模型没有生图能力），与读图优先级无关

## 边界约定（插件不影响原生 DSH）

- 插件只注入自己的客户端样式与点击拦截（限定在插件产出的图片卡片元素上），不改动 DSH 的导航、头像、市场等原生 UI
- 不动 DSH 官方源码文件；卸载即恢复原状
- 粘贴接管仅作用于"用户粘贴图片"这一动作，不拦截普通文本消息
